# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트 팀을 스스로 편성하고, 모집 마감 뒤 남은 학생은 AI가 배정안을 내며, 앱이 그 배정안을 규칙으로 검사해 확정한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생(명단 CSV의 가상 학생) | 학번·비밀번호(1234)로 로그인, 팀 목록·팀원·역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성/거부 |
| 관리자(admin) | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

## 3. 규칙
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개
- 확정한 팀은 모두 2~4명(빈 팀 없음)
- 한 팀에 주 역할이 같은 학생 2명 이상 금지
- 모든 팀에 기획자와 웹 프로그래머를 서로 다른 학생이 맡음(주 역할 또는 보조 역할)

## 4. 기능 요구사항
### 4.1 로그인
- 학번과 비밀번호. 비밀번호는 bcrypt 해시로 저장
- 관리자 계정은 앱 시작 때 `ADMIN_PASSWORD`로 만들거나 갱신. 명단을 다시 올려도 남음

### 4.2 지원과 투표
| 상황 | 결과 |
|---|---|
| 빈 팀에 지원 | 바로 승인 |
| 팀원이 있는 팀에 지원 | 대기(투표하는 때의 팀원 모두가 투표) |
| 모든 팀원 찬성 | 승인 직전 재검사 후 승인, 어기면 거절 |
| 한 명이라도 거부 | 바로 거절 |
| 팀이 꽉 참 / 주 역할 중복 / 이미 팀 있음 / 결과 기다리는 지원 있음 / 마감 / 필수 포함 역할 자리 모자람 | 막힘(접수하지 않음) |
| 투표 바꾸기 | 불가 |

필수 포함 역할 자리: 지원자가 들어간 뒤 남는 자리 수 < 아직 못 채운 필수 포함 역할 수이면 막힘. 한 학생이 기획자와 웹 프로그래머를 다 할 수 있어도 하나로만 센다.

### 4.3 마감과 배정
1. 마감: 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐
2. AI 배정: 앱이 먼저 모든 경우를 따져 규칙을 지키는 배정이 있는지 확인. 없으면 "규칙을 지키는 배정이 없음"과 이유를 보이고 AI를 부르지 않음
3. 있으면 오픈라우터 1차 → 2차 → 3차 모델. 모델마다 120초 전체 대기 제한. 응답 없음, 빈 응답, 오류, 검사 실패는 다음 모델로
4. 검사 다섯 가지: 빠짐없이 배정, 한 학생 한 팀, 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족
5. 3차까지 실패하면 앱이 백트래킹으로 찾은 배정을 씀
6. 검사를 통과한 배정안만 관리자에게 보이고, 확정하면 DB에 저장

### 4.4 화면
- 공고 2.7절의 Streamlit key를 그대로 씀(`login_student_no`, `result`, `team_N`, `apply_N`, `vote_yes_{학번}` 등)
- `result`는 "승인", "대기", "거절", "막힘" 가운데 하나로 시작
- 로그인한 화면은 `st.fragment(run_every=3)`로 3초마다 자동 갱신
- 내 팀 표시, 이미 팀/대기 지원/마감이면 지원 단추 비활성, 투표한 지원은 "내 투표: 찬성" 표시
- AI 배정 중에는 몇 차 모델의 응답을 몇 초째 기다리는지 보여 줌

## 5. 비기능 요구사항
- 키·DB 주소·관리자 비밀번호는 `.env`/Streamlit Secrets에만. 화면에는 "있음/없음"만
- DB 연결은 연결 풀 하나를 다시 씀
- 테이블 이름은 `tf_`로 시작, `schema.sql`로 남김
- DB 유일성 제약: `tf_members (team_id, slot_no)` 기본 키 + `slot_no` 1~4 + `student_id` unique
- Supabase 일시정지 방지: GitHub Actions 예약 작업으로 매일 질의
- Streamlit Community Cloud에 배포, 화면 시각은 한국 시각
