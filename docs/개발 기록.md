# 개발 기록: 클로드가 코드를 만들며 발견하고 고친 잘못

README 6항에 쓰려면 본인이 직접 재현해 화면이나 커밋으로 근거를 남겨야 합니다. 아래는 이 코드를 만든 클로드가 시험 중에 실제로 발견한 것입니다.

## 1. 120초 제한이 실제로는 지켜지지 않음
- 잘못: 시간이 지나면 다른 스레드에서 `resp.close()`를 불러 응답을 끊게 했음. 그런데 이 호출은 읽고 있는 스레드와 잠금을 다투어, 응답이 계속 조금씩 오면 닫히지 않고 기다렸음
- 발견: `tests/run_scenarios.py`의 `timeout_check`(keep-alive만 보내는 가짜 서버, 제한 3초)에서 3초가 아니라 20~30초 뒤에 끊김
- 고침: 닫기는 별도 스레드에 맡기고, 시간이 되면 기다리지 않고 바로 다음 모델로 넘어감(`ai.call_model`, `_quiet_close`). 다시 시험해 3.0초에 끊김

## 2. 빨리 끝난 AI 배정의 배정안이 사라짐
- 잘못: "AI 배정 진행 중" 상태를 배경 스레드를 시작한 **뒤에** 저장했음. 키가 없거나 모델이 바로 429를 내면 스레드가 먼저 끝나 배정안을 저장하고, 그 뒤 진행 중 상태 저장이 배정안을 지움
- 발견: 화면 흐름 시험에서 AI 배정 뒤 `admin_confirm` 단추가 나오지 않고 "이전 배정 작업이 끊김"이 보임
- 고침: 진행 중 상태를 스레드 시작 **전에** 저장(`ai.start_assignment`)

## 3. 시험 기대값을 잘못 세움(규칙 해석)
- 잘못: "주 역할 기획자·보조 웹 프로그래머 학생 + 테스터" 팀(2명)에 보고서 작성자가 지원하면 막혀야 한다고 시험을 썼음
- 실제 규칙: 들어간 뒤 남는 자리 1개 ≥ 못 채운 필수 역할 1개이므로 막지 않는 것이 맞음(공고 3장 자리 계산)
- 고침: 시험 기대값을 공고대로 고침(앱 코드는 맞았음)
